# Glint Workbench

将 Glint API 和 Glint Agent 集成到一个原生窗口，用统一侧边图标栏切换功能。

```sh
cargo run -p glint-workbench
```

默认启用 API 的原生 HTML 预览；不需要时可用 `--no-default-features` 构建。

## Windows 安装包

在 Windows 上安装 Inno Setup 6 后，从仓库根目录执行：

```sh
make win-installer PRODUCT=workbench
```

命令构建 Windows x64 release 程序，打包当前用户安装的 setup，并生成 SHA-256 校验文件。默认版本读取本项目 `Cargo.toml`。产物位于 `target/windows-workbench-installer/output/Glint-Workbench-<版本>-windows-x64-setup.exe`，校验文件为同名 `.exe.sha256`。

安装流程和 Inno Setup 模板统一位于 `packaging/windows/`，产品名称、安装标识和路径由 `products.psd1` 配置。可用 `powershell -File packaging/windows/build-windows.ps1 -Product workbench -Plan` 只查看构建参数。

支持 `VERSION`、`ISCC`、`POWERSHELL` 覆盖，例如：`make win-installer PRODUCT=workbench VERSION=0.1.0 ISCC="C:/Program Files (x86)/Inno Setup 6/ISCC.exe"`。脚本会校验版本、静态链接 MSVC 运行库，并下载和校验 Microsoft WebView2 安装引导程序。安装目录、快捷方式及卸载标识独立于 Glint API。

## 导航与顶部栏

侧栏上半部分提供 API 请求、环境、代理和请求历史；分隔线下提供 Agent 会话、伙伴、新建会话和日程；底部固定提供插件管理、MCP 调用历史、公共密码箱、Agent 设置和主题切换，并以分隔线与业务入口区分。选中图标随页面变化，主题同时应用到两个模块。

API 请求页顶部显示工作区、命令搜索、环境选择、后台任务和记录开关；环境、代理、插件和 MCP 页隐藏请求专用控件。密码箱隐藏工作区控件。Agent 会话页显示项目、会话搜索和 Provider；日程页隐藏这些控件；设置页保留设置搜索。窗口标题保持 Glint Workbench。

两个模块的 GPUI entity 在切换时保持存活，请求草稿、会话输入和后台任务不会因切换而重建。原生 HTML 预览在离开 API 时隐藏。编辑和持久化继续复用原模块实现。

## 模块与业务边界

API 和 Agent 提供 `WorkspaceSlots`（顶部栏、侧栏、内容、侧栏尺寸和主题）；Workbench 注入同一个 `ShellRenderer`，统一组装 `AppLayout`、品牌标题、导航及窗口控件。独立应用未注入宿主时自行创建外壳。切换 API 工作区也会保留宿主外壳。

页面状态由各模块的 `Page` 枚举表示，宿主使用 `Route::Api(Page)` / `Route::Agent(Page)`。互斥页面不再通过多个 `show_*` 布尔值组合。主题和导航通过模块通知同步，宿主 `render` 只选择当前模块。宿主仅在页面或主题变化时刷新导航，流式消息等模块内部更新不再触发整个 Shell 刷新。密码箱主题和显隐通过状态通知更新，不在 render 中更新其他 Entity。

`glint-api/src/workspace_service.rs` 中的 `ApiWorkspace` 持有工作区业务数据、集合／目录／请求与环境操作、版本追加、持久化、工具参数校验和脱敏审计；这些操作不依赖窗口或 GPUI Context。`workspace_adapter.rs` 将工具调用衔接到服务和现有执行器，刷新界面与调用历史。输入控件同步、窗口选择、HTTP／WebSocket 的 GPUI 任务编排以及 `ui_set` 等界面效果仍由适配层处理。

内置 Agent 调用直接返回执行结果；只有外部 MCP 传输继续使用其响应通道。两种入口共用命令校验、业务服务和审计规则，不再为进程内调用构造同步回复通道。

## Agent 操作 API

Agent 页面自动注册 Glint API 已有的全部 `glint_*` MCP 工具，可直接查询和修改当前 API 工作区的集合、目录、请求、环境及历史，也可以发送请求并查询执行结果。例如：“创建一个测试集合，新增 GET 请求，然后发送并检查响应”。无需配置 MCP 服务，也无需先打开项目。

`ToolRegistry` 统一组合普通工具、宿主工具和远程工具，缓存每次请求的宿主目录快照；`mcp::Client` 只负责远程 MCP 的连接、发现和调用。工具定义、批准判定和执行使用同一份宿主目录，避免反复构造 catalog。

内置工具通过进程内通道调用当前 API entity，复用 MCP 的参数校验、业务处理、脱敏和调用历史；修改会同步到 API 页面。外部 MCP 配置仍可使用，配置或连接失败不会移除内置 API 工具。兼容 OpenAI、Anthropic 和 ChatGPT Provider，定时任务和子代理沿用同一工具连接。

“请求批准”模式下，写操作、发送请求及显式读取敏感信息需要批准；普通只读操作直接执行。自动批准和完全访问权限模式沿用原有行为。调用会显示在 Agent 工具记录中，API 的 MCP 调用历史中来源标记为 `Glint Workbench Agent`。取消会话后，尚未开始的排队调用不会继续修改工作区；已经启动的 HTTP / WebSocket 任务使用原有 API 工具查询或取消。30 秒超时覆盖排队及返回结果：排队超时明确表示未执行；开始执行后等待超时表示结果未确认，提示查询状态／调用历史，避免盲目重试写操作。

## 数据与兼容性

沿用独立应用的数据目录和凭据存储，无需迁移；`GLINT_API_DB_PATH`、`GLINT_AGENT_DATA_DIR`、`GLINT_VAULT_DATA_DIR` 仍有效。密码箱由宿主创建单个 `VaultPage` 并注入两个模块；切换 API 工作区也复用此实例，保留解锁状态。独立运行的应用仍自行创建密码箱。

Glint Workbench 与 Glint API 共用 API 工作区的进程锁，因此同一 API 数据目录只允许一个程序运行。原有 `cargo run -p glint-api` 和 `cargo run -p glint-agent` 入口保留。

统一程序支持 `--mcp`、`--mcp-config` 和内部 `--plugin-worker` 协议，插件子进程和 MCP 自动启动可以使用当前可执行文件。API 独立程序的自动更新器不会在统一程序中启动，避免用 API 安装包覆盖整个工作台。

## 验证

```sh
cargo check -p glint-workbench -p glint-api -p glint-agent --all-targets
cargo test -p glint-api -p glint-agent hosting::tests
cargo test -p glint-workbench
```

## 伙伴与自主唤醒

会话页侧栏统一提供“按项目 / 按伙伴 / 按日期”分组。按伙伴时，同一伙伴在不同项目的会话汇集到其分组，尚无会话的伙伴仍保留入口；分组的“+”使用当前项目新建该伙伴会话，“设置”进入对应伙伴设定。分组方式随本地历史保存。

输入框底部的伙伴选择器，以及 `@`／“+”上下文面板的“伙伴”分组，都可以选择当前交流对象。新建空白会话直接绑定；已有消息、正在执行或已有排队请求的会话会另建会话并带上当前草稿与图片，保留原会话的身份。选择伙伴会消费光标处临时的 `@关键词`，不向提示词插入身份指令；伙伴记忆与工具上下文仍由实际会话绑定决定。切换历史会话会同步选择器，新会话沿用当前伙伴。

伙伴页采用独立伙伴列表与详情区，提供“近况 / 记忆 / 唤醒计划 / 设定”分页。近况页以真实关注点、目标和经历为主，右侧展示下一次唤醒与成长习惯；窄窗口自动将右栏排到下方。记忆页支持活跃、沉睡和固定筛选，展开后查看正文、来源与管理操作。唤醒页可暂停、恢复或进入日程编辑。

“设定”中可选择本地 PNG、JPEG、WebP 图片作为头像，也可使用符号。图片最多 20MB / 2500 万像素，导入时生成最长边 512 像素的 PNG，复制到 Agent 数据目录的 `partners.avatars/<伙伴ID>/`，数据库仅保存本地引用。选择后先预览，点击“保存设定”生效；支持更换图片及恢复默认，原图移动或删除不影响已保存的头像。

详情顶部的删除按钮会弹出二次确认，默认聚焦“取消”，支持 Escape 退出。确认后删除伙伴身份、个人记忆、成长证据、所属日程与本地头像，历史会话保留并解除绑定。运行中的任务或日程会阻止删除；旧的排队保存也不会恢复已删除的伙伴绑定。

侧栏的“伙伴”页可以创建空白伙伴。名字、头像符号和设定都可后补；选择伙伴开始会话后，身份随会话保存，新会话沿用上次选择的伙伴。专家可通过设定描述，多个伙伴可通过 `partner_list` 和 `subagent({partner_id, task})` 委派协作；被指派伙伴使用自己的身份和记忆，执行记录沿用子代理详情页。

记忆分为三种访问方式：每次请求携带身份、最近七天的经历、固定记忆和未完成事项；自动召回结合当前话题筛选活跃记忆；`memory_search` / `memory_read` 和伙伴页搜索可查找沉睡记忆。项目细节保留在项目内，跨项目携带抽象经历；各伙伴个人记忆隔离，共享的原有全局／项目记忆继续可读。伙伴页可查看正文和来源会话、固定记忆，或确认删除一段经历及其派生记忆和人格证据。删除聊天不自动删除已形成的伙伴记忆。

回复、失败及停止记录随会话保存时，在同一 SQLite 事务中写入经历队列。后台使用当前启用模型整理记忆、关注目标、承诺及人格候选；失败退避重试，重启后恢复过期租约。普通检索不强化记忆；有再次有效提及的证据才增强。人格候选需要至少三次不同会话的支持才进入常驻身份；名字可以由模型提出，在伙伴页采用。

伙伴列表顶部的“导入伙伴”选择 `.glint-partner.json` 迁移文件；伙伴标题旁的下载图标和“设定 → 迁移伙伴 → 导出伙伴”导出当前已保存的伙伴。迁移文件自带头像图片，无需另拷头像目录，包含各项目范围的记忆、强度、固定状态、人格证据、经历、目标和唤醒计划。原始会话记录、项目文件和账号凭据不包含在伙伴迁移文件中；记忆的原会话来源标识和项目路径保留。

导入始终新建伙伴并重建内部 ID 与证据关联，不覆盖同名伙伴。导入后的自主唤醒关闭、日程暂停，进行中的目标转为暂停；日程需检查项目路径并重新选择本机模型后再启用。头像、记忆和关系校验通过后才写入，失败回滚。导出前需保存未提交的设定；选择文件时取消不会修改伙伴。

“自主唤醒”默认关闭。开启后先在 15 分钟后安排一次回顾，由伙伴通过现有 `schedule_create` / `schedule_update` / `schedule_delete` 自行选择后续唤醒时间、目的及 `wake_mode`：

- `reflect`：读取项目和历史、整理自身记忆、安排后续唤醒。程序阻止写文件、运行命令、调用外部工具和委派。
- `work`：恢复伙伴身份、记忆、项目及模型，执行明确的任务，沿用输入框的工具审批模式。

开启自主唤醒授权伙伴管理自己的唤醒日程；不授予额外文件或外部工具权限。每个伙伴滚动 24 小时最多自主唤醒 3 次，两次至少间隔 15 分钟，最多保留 8 个待唤醒日程。关闭会禁用尚未运行的自主唤醒；已运行的任务通过会话停止。伙伴不能在自主唤醒中修改用户手动安排的日程。未开启自主唤醒时，仍可手动安排绑定伙伴的单次／每日／每周任务，或在伙伴页点选目标“开始推进”。日程页可查看所属伙伴并切换两种唤醒模式。

唤醒复用应用内调度器：应用关闭时不执行，不会唤醒电脑或启动已退出的应用；重新打开后补执行到期任务一次。执行中断记录失败，不自动重复执行。自动记忆整理会使用模型额度；真实模型效果需配置供应商后验证。
